# Context Management

会話は消える。ファイルは残る。データでみる沖縄 (okinawa-in-data) で意思決定や進捗を保全するための運用方針。本ガイドは姉妹サイト EduEvidence JP / EduLaw JP / EduWatch JP と同一思想で、固有事情(データ資産の扱い・Cloudflare Workers 静的アセット構成)のみ本リポジトリ向けに調整している。

## 基本原則 — File is the memory

Claude Code とのセッションは context window の上限に達すると圧縮(コンパクション)される。圧縮時に失われやすいのは「議論の過程」「却下した選択肢の理由」「試行錯誤のログ」。これらをファイルに書き出しておけば、圧縮を跨いで保全できる。

| レイヤ | 役割 | 配置 |
|---|---|---|
| **`.claude/state/active.md`** | 現在のセッションのチェックポイント。マイルストーンごとに更新 | `.gitignore` で git 追跡しない(私的状態) |
| **`docs/decisions/<連番>-*.md`**(ADR) | 主要意思決定の不変記録 | git 追跡、Public |
| **`data/datasets/<id>/notes.md`** | 変換の判断(セル結合の解釈・欠損の扱い)の監査記録 | git 追跡、Public |
| **`docs/sessions/<日付>.md`**(任意) | 1 セッションの議事録要約 | git 追跡しない場合は `.gitignore` |
| **メモリ**(Claude Code のユーザー領域) | 運営者の個人的な嗜好・私的方針 | Private、リポジトリ外 |
| **`CLAUDE.md`** | プロジェクトの恒久的な規約 | git 追跡、Public |

## レイヤ間の振り分け指針

- **「決まったこと」** → ADR(`docs/decisions/`)
- **「いま作業中の具体内容」** → `.claude/state/active.md`(逐次更新)
- **「データ変換の判断根拠」** → 該当データセットの `notes.md`(一次資料・欠損・断層の扱い)
- **「変わらない規約・ルール」** → `CLAUDE.md`
- **「運営者の個人的な嗜好」** → メモリ(リポジトリ外)
- **「公開しない議事録」** → `.gitignore` 配下(必要なら `docs/sessions/`)

迷ったときの判断:**「他のメンテナーが半年後に読んで意味があるか」=Yes なら ADR、No なら state / メモリ**。

## active.md の運用

`.claude/state/active.md` は **生きたチェックポイント**。以下のタイミングで更新する:

- 主要な意思決定が確定した時(ADR を起こすほどでもない小規模な合意も含む)
- PR を作成した / マージした時
- 別ブランチに切り替える時
- gather(データ取得)や変換で同じ問題を 2 回以上試行錯誤した時(失敗ログとして)
- セッション終了時

### 共通テンプレート(全プロジェクト統一、2026-05-21 6 サブ節に拡張)

各セッションのエントリは「直近の状態(YYYY-MM-DD ...)」のマーカー行の下に **下記 6 サブ節** を持つ。**マーカー行の書式は 1 つに固定されていない** — 下のコード例は見出し 2 段だが、実体は太字(`**直近の状態(...)**`)と混在する(実測は「アーカイブ手順」の表)。新しいエントリを既存のものより上に積む(時系列降順)。2026-05-21 に Anthropic Claude Code engineer Thariq Shihipar(@TRQ212)の implementation-notes プロンプト(逸脱・判断・トレードオフ・未解決を実装中にリアルタイム記録)を採用し、「実装ノート」サブ節を追加した。

```markdown
## 直近の状態(YYYY-MM-DD セッションN・**PR #X マージ済+後処理完了+live 反映確認済(main `xxxxxxx`)**)

### 本タスクで作成 / 変更

- **PR #X**: 内容を 1〜2 文で
- 変換・収録したデータセット / 触れたファイルを列挙

### 検証

- `npm run check` / `npm run check:data` / `npm run build` の実行結果
- 変換 assert(一次資料アンカー値の突合)や live 反映の観測値

### 実装ノート(逸脱・判断・トレードオフ・未解決)

- Plan / 事前合意で握った仕様から実装中に変えた点
- 仕様に書かれていなかった判断(命名・閾値・スコープ縮小など)
- トレードオフ(複数選択肢があった場合、何を選んで何を捨てたか)
- 未解決の判断 / 次の AI または次セッションが確認すべき Open questions
- 逸脱が一切なかった場合は「逸脱なし」、計測・後処理中心の回は「実装なし(計測中心 / 後処理のみ)」と明示(空欄禁止)

### 採択された規約 / 仕組み(本セッション内で確定)

- **<規約名>**: 要点(リポジトリ外の個人メモを指す番号ではなく、規約の内容を書く)
- **ADR NNNN**: docs / ADR 化したもの

### サイト稼働状況

- published / draft データセット数、収録法・指標のカバレッジ
- Cloudflare Workers(wrangler.jsonc)デプロイ状況・live 反映確認

### Next Action

- 短期(優先順)と中長期を 5〜10 件で列挙
```

### サブ節の使い分け

- **本タスクで作成 / 変更**: PR / データセット単位で記述。gather(取得)と convert(変換)を跨ぐセッションでは両方を明示する。
- **検証**: 静的検証(`check` / `check:data` / `build`)+ 変換の突合(一次資料アンカー値との assert)+ live 実測を一覧。
- **実装ノート(逸脱・判断・トレードオフ・未解決)**: Plan Mode で合意した仕様と実装中の判断の乖離を埋めるサブ節。Design decisions / Deviations / Tradeoffs / Open questions の 4 カテゴリを意識する。ADR ほど重くない判断を主対象とし、ADR で残すべき重大決定はそちらに昇格させる。**逸脱が無くても「逸脱なし」、実装を伴わない回でも「実装なし(計測中心 / 後処理のみ)」と必ず書く(空欄禁止)**。欠落は運営者の手元のグローバル hook が新セッションブロック起票時に検知し、追記を促す。設計判断を「採択された規約」に紛れさせない(規約=後続が参照する確定事項 / 実装ノート=その場の判断・逸脱)。由来は Anthropic Claude Code engineer Thariq Shihipar(@TRQ212)の 2026-05-18 X 投稿。
- **採択された規約 / 仕組み**: ADR・docs ガイドラインなど、後続セッションが参照する規約を明示する欄。なければ省略可。
- **サイト稼働状況**: published / draft データセット数を主指標とし、Cloudflare Workers のデプロイ・live 反映確認をスナップショットする。
- **Next Action**: 次セッションの起点。短期(優先順)/ 中長期 / 横断課題で分けてもよい。

### 過去エントリの扱い

- 直近 1〜2 セッション分は本ファイル内に時系列で残す
- 古いエントリは要点だけ残して圧縮するか、`.claude/state/archive/` 側に移して参照する
- どこまで残すかはマシンの記憶ではなく、**次セッションの再開時に必要な情報量** で判断

### サイズ管理とアーカイブ運用

active.md がセッション履歴で肥大化すると、セッション開始時の読み込みコストが増え Lost-in-Multi-Turn のリスクが上がる。下記の閾値とフローで定期的に整理する。

#### サイズの目安

| 行数 | 目安トークン | 影響 |
|---|---|---|
| 〜500 行 | 〜30k | 推奨ゾーン |
| 500〜1,500 行 | 30k〜90k | 体感影響なし |
| 1,500〜3,000 行 | 90k〜180k | 読み込み時間増、検索精度低下 |
| 3,000 行超 | 180k+ | Lost-in-Multi-Turn リスク域 |

#### 自動感知

`.claude/hooks/check-active-size.sh` が SessionStart hook として登録済(`.claude/settings.json`)。`wc -l` で行数を測り、**1,500 行**を超えるとセッション開始時に additionalContext へ警告を注入する。閾値を変えたい場合はスクリプト内 `THRESHOLD` を直接編集する。

#### アーカイブ手順

1. 切り出し位置を **union パターン**で確認する。

   ```sh
   grep -nE '^(#+ +)?\*{0,2}直近の状態' .claude/state/active.md
   ```

   **マーカー行の書式を 1 つに決め打ちしない。** 行頭の接頭辞が `**` / `# ` / `## ` の 3 通りあり、
   **この履歴の中で時期によって変わっている**。マーカー語の後ろも一定ではない
   (`(2026-09-01)` / `**: 2026-09-01` / ` (2026-09-01)`)ので、**日付の位置を当てにしない**。
   上のパターンが見ているのは接頭辞だけで、後ろは見ていない。実測(2026-09-01):

   | | 太字 `**` | `# ` | `## ` |
   | --- | --- | --- | --- |
   | 現在の `active.md` | 22 | 0 | 16 |
   | `archive/` 全体 | 0 | 0 | 74 |

   取りこぼしたブロックは**消えず、隣のブロックに吸収される**。どちらへ転ぶかは、
   決め打ちした書式が新しい側か古い側かで決まる(履歴は新しいものが上に積まれる):

   - **新しい側に決め打ち**すると、古い側が丸ごと最後の 1 ブロックに吸収される。
     症状は「ブロック数が少ない」ではなく「**最後の 1 ブロックだけ異様に長い**」
   - **古い側に決め打ち**すると、`TRIM_LINE` がずっと下に落ちる。
     症状は「**アーカイブしたのに `active.md` が縮まない**」

   どちらも件数だけ見ていると気づけない。**0 件や不自然に少ない件数を
   「切り出す履歴が無い」と読まないこと。**

   **接頭辞を直した後も、マーカーの間隔を見る。** 隣り合うマーカーの間隔が 1 つだけ突出して
   広ければ、そこに取りこぼしがある。書式違い以外に `## 前回の状態(...)` `## 途中経過の記録(...)`
   `## セッション #N (...)` のように**語そのものが違うブロック**が実在する(最後の形は
   「直近の状態」を 1 度も含まない)ので、**書式の列挙では塞ぎきれない**:

   ```sh
   grep -nE '^(#+ +)?\*{0,2}直近の状態' .claude/state/active.md | cut -d: -f1 |
     awk 'NR>1{print $1-p" 行空き (行 "p")"} {p=$1}' | sort -rn | head -5
   ```

   **`(旧)` / `(過去)` を接頭辞の直後に付けた行**(`## (旧)直近の状態 …`)は意図的に降格した
   マーカーで、切り出し位置にはならない。上のパターンはこれを拾わない。
2. 残すブロックの境界となる「次に古いセッション開始行」を `TRIM_LINE` とする(その行の **前** までを残す)
   - **並行セッションが同じ `active.md` に書いていることがある。** 新しいブロックは冒頭に積まれるので、
     読み込みと書き戻しのあいだに割り込まれると相手のブロックを消す。行番号ではなくブロック見出しの
     文字列で切り出し位置を決め、書き戻す直前に mtime が変わっていないことを確かめる
   - **チェックアウトも共有される。** 同じリポジトリで別セッションが動いていると、こちらの `git switch`
     が相手の HEAD ごと動かす。着手前に `.claude/state/active.md` の mtime を見て、数分以内に
     更新されていれば worktree を使う(`git worktree add <path> -b <branch> --no-track origin/main`)
3. 退避前の複製を取り、置き場を用意する。**手順 4〜6 は `.claude/state/` の中で実行する**
   (リポジトリルート基準なのは手順 1 の grep だけ)。

   ```sh
   cd .claude/state
   mkdir -p archive
   NAME=pre-YYYY-MM-DD-<短い説明>.md
   PRE=$(mktemp); cp active.md "$PRE"      # 手順 6 の diff に使う
   ```

4. アーカイブを作る。**ヘッダの行数は数える。推測しない**(実測で 0〜10 行に散っており、
   ヘッダを持たないアーカイブも実在する)。

   ```sh
   printf '# active.md archive — <範囲と主題>\n\n<1〜3 行の説明>\n\n---\n\n' > "archive/$NAME"
   HDR=$(wc -l < "archive/$NAME" | tr -d ' ')
   tail -n +"$TRIM_LINE" active.md >> "archive/$NAME"
   ```

5. `active.md` を切り詰める。

   ```sh
   TMP=$(mktemp)
   head -n "$((TRIM_LINE-1))" active.md > "$TMP"
   printf '\n<!-- <範囲> は archive/%s へ退避 -->\n' "$NAME" >> "$TMP"
   mv "$TMP" active.md
   ```

   **行範囲の切り出しに `sed` を使わない。** 以前ここは手順 4 が `sed -n "${TRIM_LINE},$p"`、
   手順 5 が `sed -n "1,$((TRIM_LINE-1))p"` で書かれていた。**同じ二重引用符の中で `$` の
   エスケープの向きが逆**になる — 手順 4 の `$` は sed の「最終行」なので `\$` と守る必要があり、
   手順 5 の `$((…))` はシェルの算術なので守ってはいけない。実測では 6 本のうち 4 本が手順 4 側を、
   2 本が手順 5 側を取り違えており、**両方通る組み合わせが 1 本も無かった**。
   `$` の出ない `tail -n +N` / `head -n N` ならこの取り違えが起きない
   (`head -n -N` の負数は macOS では使えないので、正の行数で指定する)。

   **`{ …; } > tmp && mv` の形にしない。** グループの終了ステータスは最後の `printf` の
   ものになるので、**切り出しが落ちても 0 で返り `mv` が発火する**。実測では、エスケープ 1 文字の
   違いで 1198 行・144 KB の `active.md` が **9 バイトになり、それでも exit 0 だった**。
   `active.md` は git 追跡外なので、手順 3 の複製が無ければ復旧できない。

   **`/tmp/t` のような固定名を使わない**(手順 2 の並行セッションと衝突する)。
   **末尾の改行を落とさない**(次に積むブロックが連結され、マーカーが引けなくなる)。

6. 検証(4 つとも行う)

   ```sh
   M='^(#+ +)?\*{0,2}直近の状態'

   wc -l active.md                                          # A. 推奨ゾーン内か

   { head -n "$((TRIM_LINE-1))" active.md                   # B. 無損失(出力が空なら OK)
     tail -n +"$((HDR+1))" "archive/$NAME"; } | diff - "$PRE"

   echo "$(grep -cE "$M" active.md) + $(grep -cE "$M" "archive/$NAME") \
        / $(grep -cE "$M" "$PRE")"                           # C. 左辺の和 = 右辺

   tail -n +"$((HDR+1))" "archive/$NAME" | head -1 | grep -qE "$M" \
     && echo 'D ok' || echo 'D NG: アーカイブがマーカーで始まっていない'
   ```

   **D を省かない。** `TRIM_LINE` を「切り出す最初の行」ではなく「残す最後の行」と読むと
   境界が 1 行ずれるが、**B も C も素通りする**(結合すれば元に戻るし、マーカーはどちらかに
   1 つあるだけなので数も合う)。実測でこのずれを捕まえたのは D だけだった。ずれると
   `active.md` の末尾に本文の無いマーカーが残り、アーカイブはマーカーを失った本文から始まる。

   B が 1 行だけずれたときの原因は `HDR` の数え違いか、`head` に渡す行数の間違い。
   **件数ではなく `diff` の中身を読む。**

   4 つを残しているのは、**どれか 1 つでは足りないことを実測したから**(2026-09-01・
   実ファイル 489 行に 5 通りの壊し方を入れた):

   | 壊し方 | A | B | C | D |
   | --- | --- | --- | --- | --- |
   | (正しく実行) | — | 通 | 通 | 通 |
   | 境界を 1 行ずらす | — | 通 | 通 | **落** |
   | ブロックを 1 つ落とす | — | **落** | **落** | 通 |
   | `HDR` を数え違える | — | **落** | 通 | **落** |
   | 手順 4 が失敗する | — | **落** | **落** | **落** |
   | 手順 5 が `active.md` を壊す | — | **落** | **落** | 通 |

   A(行数)はどの壊し方も止められない。**旧版の検証は A だけだった。**

#### 整理履歴

- **2026-08-02(第 1 回)**: **2,225 行 → 161 行**。セッション 41(2026-08-02 の 5 ブロック)のみ残し、セッション 40 続 2 以前を `.claude/state/archive/2026-07-05_2026-08-01_sessions-01-40.md`(2,072 行)へ移送した。**当時「87 ブロック」と記録したが、これは `^## ` の見出しを全部数えた値**で、「直近の状態」マーカーは 74、残る 13 は `## 前回の状態(...)` `## 途中経過の記録(...)` など**別の語で書かれたブロック**だった(2026-09-01 に実測)。要約・改変はせず時系列降順のまま移し、active.md の末尾に参照先を示す HTML コメントを残している。archive も `.claude/state/` 配下のため git 追跡外。
- **2026-09-02(第 2 回)**: **1,539 行 → 191 行**。2026-08-31 以降の 6 ブロックを残し、2026-08-02(セッション 41)〜2026-08-27 の 34 ブロックを `.claude/state/archive/2026-08-02_2026-08-27_sessions-41-onward.md`(1,357 行・うちヘッダ 7 行)へ移送した。上の「アーカイブ手順」1〜6 を書かれているとおりに辿り、検査 4 つ(191 行 / diff 空 / マーカー 6 + 34 = 40 / アーカイブ先頭がマーカー)を通した。

### 例外と運用の幅

- 6 サブ節すべてが毎回必須ではない。短いセッションでは「本タスクで作成 / 変更」+「実装ノート」+「Next Action」だけでもよい
- gather / 計測のみのセッションでは「本タスクで作成 / 変更」を「取得・観測した内容」に読み替えて使い、実装ノートは「実装なし(計測中心)」とする

## ADR の運用

`docs/decisions/<連番>-<短いスラッグ>.md`(例: `0001-build-time-svg-visualization.md`)。連番は 4 桁。運用方針と索引は `docs/decisions/README.md` を参照する。

各 ADR は以下のテンプレに従う:

```markdown
# NNNN. タイトル

- 状態: 採用 / 撤回 / 上書き(00NN で上書き、等)
- 日付: YYYY-MM-DD
- 関連 PR: #N, #M

## 背景

何が問題で、なぜ決定が必要だったか。

## 検討した選択肢

- A) ...
- B) ...
- C) ...

## 決定

採用した案と理由。

## 帰結

- 良い帰結
- トレードオフ / 既知のリスク

## 撤回 / 再検討の条件

何が起きたら見直すか。
```

ADR は **不変** が原則。決定が覆ったら新規 ADR を起こし、旧 ADR の「状態」を `撤回(00NN で上書き)` にする。

## 圧縮(compaction)対策

### 自発的に圧縮するタイミング

- context 使用率が 60〜70% に達した時(限界まで待たない)
- 関連の薄いタスクに切り替える時(`/clear` を使う)
- 「同じ変換・取得を 2 回試して失敗した」直後(リセットして再挑戦)
- ファイルへの書き出し / コミット / PR 作成の直後(自然な区切り)

### 圧縮直前の準備

`.claude/hooks/pre-compact.sh` が自動的に以下を会話に dump する:

- `.claude/state/active.md` の内容(現在のセッション状態)
- git の uncommitted / staged / untracked ファイル一覧

これにより、圧縮後のサマリにも必ず active.md への参照とファイル変更状態が含まれる。

### 圧縮直後の復元

`.claude/hooks/post-compact.sh` が「active.md を読み直せ」というリマインダーを出す。圧縮後は最初に `.claude/state/active.md` を読むことで、ファイル化されている決定と進行状態を復元できる。

## サブエージェント運用との連携

サブエージェントは独立したコンテキストで走るため、メインセッションの context を圧迫しない。以下を使い分ける:

- **メインで読む**: 1〜2 ファイルだけが対象、結果をすぐ判断に使うとき
- **サブエージェントに投げる**: 複数ファイル横断、大きな PDF / raw テキストの走査、gather(取得)フェーズ

サブエージェント結果が長い場合は、要点のみを active.md に転記し、生の出力は破棄する。

## セッション境界での運用

### セッション開始時

1. `.claude/state/active.md` を読む(最優先、何もしていない時でも)
2. 直近の git log / git status を確認
3. 進行中の PR を `gh pr list` で確認
4. 必要なら関連 ADR(`docs/decisions/`)に目を通す

### セッション終了時

- active.md に「次回の起点」を 1〜2 行書く
- 主要な意思決定があれば ADR を起こす
- 必要に応じて `docs/sessions/<date>.md` を作って議事要約
