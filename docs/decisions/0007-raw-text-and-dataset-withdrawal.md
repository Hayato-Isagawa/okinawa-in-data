# 0007. 本文を再配布できないデータセットは生テキストを入れず、取り下げは meta.json のリネームで行う

日付: 2026-11-19
状態: 採用

## 背景

このサイトは、数値を一次資料と逐語照合した証跡として、出典を `pdftotext -layout` した生テキストを `raw/` に置くことを原則にしている(README.md「データの信頼性」)。`npm run check:data` は、`published` のデータセットで `raw/` が空だとエラーにする。

ところが、出典によっては本文をリポジトリで再配布できないか、できるかどうかを確かめられていない。2026-11-19 時点で、規約が理由で生テキストを入れていないのは次の 2 つで、理由は別々(容量や姉妹データセットとの原本の共有を理由に `raw/README.md` だけを置くデータセットもあるが、この ADR の対象ではない)。

- **`kodomo-chosa-konkyu-keinen`**: 出典の沖縄県サイトの利用規約は、著作権法で認められた場合を除いて転用・引用を認めていない。県に利用を照会して得た回答の範囲は `meta.json` の `license.note` にある(出典を明示した掲載と、内容を変えない再構成)。報告書本文の転載がその範囲に入らないことは `raw/README.md` に書いてある
- **`ses-gakuryoku-hogosha-chosa`**: 文部科学省サイトの利用規約(公共データ利用規約に準拠)のもとで、**数値は掲載している**。一方、報告書は国立大学法人が作った委託研究の成果で、規約が対象外とする「国以外の者」の著作物に当たる可能性があり、**本文を再配布できるかは確認できていない**。数値の掲載と本文の再配布は別の判断で、前者ができても後者ができるとは限らない

もう 1 つ、公開したデータセットを止める方法が要った。2026-07-13 に、`kodomo-chosa-konkyu-keinen` が県への利用確認を終えないまま公開されていたと分かり、確認が取れるまでサイトから外した。2026-10-30 に県の回答を受け取り、2026-11-01 に戻した(経緯は同データセットの `notes.md`「一時非公開」「公開再開」)。

## 検討した選択肢

監査証跡:

- **生テキストを入れず、`raw/README.md` に理由と原本の取得先を書く(採用)**: `check:data` の「`raw/` が空でない」を満たしつつ、第三者が同じ原本を取得して照合できる
- **生テキストを入れる**: 規約上できない、またはできるか確認できていない再配布になる
- **`raw/` を空にして検査の対象から外す**: 照合の手がかりが何も残らない

取り下げ:

- **`meta.json` を `meta.json.hold` にリネームする(採用)**: ローダーは `meta.json` の無いディレクトリを読まないので、ページ・CSV / JSON の配信・sitemap から一度に外れる。`notes.md` と `raw/` は残り、戻すときはリネームを戻すだけ
- **`status: "draft"` にする**: draft はサイトに「検証中」として出るので、取り下げにならない
- **ディレクトリを削除する**: `notes.md` と `raw/README.md` の記録ごと消える。戻すときに作り直しになる

## 決定

1. 出典の規約で本文を再配布できないもの、または再配布できるか確認できていないものは、生テキストをリポジトリに入れない。`raw/README.md` に理由と原本の取得先を書き、変換スクリプトが読む生テキストは `.gitignore` で追跡しない
2. 公開したデータセットを止めるときは、`meta.json` を `meta.json.hold` にリネームする

## 帰結

- 生テキストを入れないデータセットは、リポジトリだけでは照合を再現できない。原本の URL が変わると、取得先も辿れなくなりうる
- 取り下げで自動的に外れるのは、ローダーを通る出力だけ。次は取り下げるときに手で外す(2026-07-13 も、KeyFigures のカード・テーマページの図・6 つのデータセットの `relatedDatasets` を外した)
  - `getDataset(id)` で id を直接引く箇所(KeyFigures・MapExplorer など): 見つからないとビルドが落ちる
  - 他のデータセットの `meta.json` の `relatedDatasets`: `npm run check:data` は meta.json の有無を見ずにディレクトリ名で照合するので通り、ビルドも通る。関連データセットのリンクが 404 になる
  - ページ本文から直接張ったリンク(例: `src/pages/themes/education-poverty.astro`): 404 になる
- 取り下げ中のデータセットが外れていることを E2E(`tests/datasets.spec.ts`)で見られるのは、取り下げ中のものが実在するときだけ。ローダーの除外そのものは `src/lib/__tests__/datasets.test.ts` が一時ディレクトリで見ている

## 撤回 / 再検討の条件

- 出典の規約が変わるか、権利者から本文の再配布の許諾を得たとき。そのデータセットは生テキストを入れる側に移す
- 取り下げ中であることをサイト上で示す必要が出たとき(リネームでは何も出ない)
